# 开源分享：高通 SDM660 + WCN3990 主线 Linux Wi-Fi 断连与热点切换固件崩溃根治方案

> **适用芯片**：Qualcomm Snapdragon 660 (SDM660) / 636 / 630 / 670 / 710  
> **适用无线网卡**：Qualcomm WCN3990 (`ath10k_snoc`) 内置集成 Wi-Fi  
> **适用机型**：Xiaomi Mi Note 3 (`jason`), Redmi Note 5 (`whyred`), Xiaomi Mi 6X (`wayne`), Xiaomi Mi Max 3 (`nitrogen`), Smartisan Nut Pro 2 等搭载 SDM660 平台的设备  
> **内核版本**：Linux 6.x ~ 7.x 主线内核  

---

## 一、 背景与故障现象

在将高通骁龙 660 系列设备移植至主线 Linux（如 Debian、postmarketOS、Alpine）并驱动 WCN3990 Wi-Fi 后，机友们常常会遇到一个极其隐蔽且致命的问题：

1. **首次开机连接正常**：冷启动进入系统后，连接预设的 Wi-Fi 热点通常可以正常获取 IP 并上网；
2. **切换热点或断连瞬间暴毙**：
   - 当在图形桌面（如 GNOME Settings / Phosh 设置面板）点击另一个 Wi-Fi 热点进行切换；
   - 或者使用命令行 `nmcli con up <SSID>` / `nmcli dev disconnect wlan0` 断开当前连接；
3. **连锁反应**：
   - Wi-Fi 立即掉线；
   - 系统随后完全无法搜索到周围的任何 Wi-Fi 信号（`nmcli dev wifi list` 提示设备不可用或扫描超时）；
   - 控制台或 `dmesg` 抛出 Hexagon DSP 调制解调器致命错误，触发基带子系统重启（SSR, Subsystem Restart）：
     ```text
     [  249.251183] qcom-q6v5-mss 4080000.remoteproc: fatal error received: err_qdi.c:459:EF:wlan_process:1:cmnos_thread.c:3285:Asserted in wlan_vdev.c:_w
     [  249.251210] remoteproc remoteproc0: crash detected in 4080000.remoteproc: type fatal error
     ```

## 二、 底层致命根因深度剖析

通过开启内核 `ath10k` 的全量调试追踪（`debug_mask=0xffffffff`）并抓取崩溃瞬间的微秒级时序，锁定了 Hexagon 固件的断言入口：
`cmnos_thread.c:3285:Asserted in wlan_vdev.c:_wlan_vdev_down`。

### 1. Linux mac80211 体系的调用时序
在 Linux `mac80211` 无线子系统中，当用户发起断开连接或漫游切换时：
1. `mac80211` 首先下发 `BSS_CHANGED_ASSOC (assoc=0)` 事件；
2. 该事件直接回调驱动层函数 `ath10k_bss_disassoc()`；
3. 上游 `ath10k` 驱动历史遗留逻辑（针对早年 PCI/USB 外置网卡芯片如 QCA988x）在 `ath10k_bss_disassoc()` 中**立即向芯片固件发送了 `WMI_VDEV_DOWN_CMD`（`ath10k_wmi_vdev_down`）**；
4. 直到此步骤完成后，`mac80211` 才会进入 `__sta_info_destroy_part2()`，调用驱动的 `drv_sta_state(STA_NOTEXIST)` 去注销 AP 的 peer 节点。

### 2. 高通移动端 WCN3990 固件的硬性铁律
高通移动端 WCN3990 是通过 SNOC（System Network-on-Chip）总线与 Hexagon MSS（Modem Subsystem）紧密绑定的芯片，其运行的专有固件有严格的状态机生命周期要求：
> **固件断言约束**：在向虚设备（vdev）下发 `VDEV_DOWN` 命令时，**该虚设备名下的所有关联 peer 计数必须为 0**（`vdev->num_peers == 0`）。

如果驱动在 peer 节点尚未删除之前就下发了 `VDEV_DOWN`，固件内部检测到 `vdev->num_peers > 0`，会立刻触发致命硬件断言 `Asserted in wlan_vdev.c:_wlan_vdev_down`！
这一断言直接让 Hexagon 调制解调器崩溃，导致射频总线关闭，Wi-Fi 彻底失效。

## 三、 架构级修复方案（Patch 0003）

既然固件要求必须先注销 peer、后关闭 vdev，我们必须在驱动层对两者的调用时序进行**生命周期解耦**。

### 核心改动点（`drivers/net/wireless/ath/ath10k/`）

1. **引入延迟下发标记**：
   在 `core.h` 的 `struct ath10k_vif` 中增加 `bool needs_vdev_down;` 状态标记：
   ```c
   struct ath10k_vif {
       ...
       bool is_started;
       bool is_up;
  +    bool needs_vdev_down;
       ...
   };
   ```

2. **拦截断连时的过早 DOWN**：
   在 `mac.c` 的 `ath10k_bss_disassoc()` 中，对于 STATION 客户端模式，跳过直接下发 `wmi_vdev_down`，改为标记延迟：
   ```c
   if (vif->type == NL80211_IFTYPE_STATION) {
       /* 延迟 vdev_down 直到 station peer 在 ath10k_sta_state 中被彻底删除 */
       arvif->needs_vdev_down = true;
   } else {
       ret = ath10k_wmi_vdev_down(ar, arvif->vdev_id);
       ...
   }
   ```

3. **重构 peer 注销与 DOWN 的因果次序**：
   在 `mac.c` 的 `ath10k_sta_state()` 处理 `IEEE80211_STA_NOTEXIST` 时：
   - **第一步**：优先调用 `ath10k_peer_delete(ar, arvif->vdev_id, sta->addr)`，将 AP 从芯片固件的 peer 表中彻底剔除；
   - **第二步**：此时固件内部的 peer 计数归零，安全触发被延迟的 `ath10k_wmi_vdev_down(ar, arvif->vdev_id)` 并重新计算发射功率：
   ```c
   ret = ath10k_peer_delete(ar, arvif->vdev_id, sta->addr);
   ...
   if (vif->type == NL80211_IFTYPE_STATION && arvif->needs_vdev_down) {
       ath10k_dbg(ar, ATH10K_DBG_MAC,
                  "mac vdev %i executing deferred vdev_down after peer delete\n",
                  arvif->vdev_id);
       ret = ath10k_wmi_vdev_down(ar, arvif->vdev_id);
       if (ret)
           ath10k_warn(ar, "failed to down vdev %i: %d\n", arvif->vdev_id, ret);
       arvif->needs_vdev_down = false;
       ath10k_mac_txpower_recalc(ar);
   }
   ```

4. **异常路径兜底保护**：
   在 `ath10k_vdev_stop()` 和 `ath10k_mac_op_unassign_vif_chanctx()` 中，检查若仍有未下发的 `needs_vdev_down`，执行兜底清理；并在 `ath10k_bss_assoc()` 中复位该标记。

## 四、 真机实测验证

我们在小米 Note 3（SDM660 + WCN3990）上编译该补丁并实测：

* **自动化交替切换压力测试**：
  在 5GHz 热点与 2.4GHz 热点之间进行连续交替切换与强制重新扫网（Rescan）：
  ```bash
  for i in {1..5}; do
      nmcli c up MyHotspot-2.4G
      nmcli dev wifi list --rescan yes
      nmcli c up MyHotspot-5G
      nmcli dev wifi list --rescan yes
  done
  ```
* **实测结果**：
  - 10 次切换 100% 毫秒级成功激活；
  - 切换与断开过程中，内核无任何 `fatal error` 或 `Asserted in wlan_vdev.c` 报错；
  - 随时打开设置面板，周围 10+ 个 Wi-Fi 信号毫秒级实时刷新。

## 五、 如何在你的内核中使用该补丁

本仓库已将该补丁独立导出为标准 patch 文件：
[`patches/0003-ath10k-wcn3990-fix-disassoc-firmware-assert.patch`](../patches/0003-ath10k-wcn3990-fix-disassoc-firmware-assert.patch)

### 应用方法：
```bash
cd your-linux-kernel-source/
patch -p1 < 0003-ath10k-wcn3990-fix-disassoc-firmware-assert.patch
make -j$(nproc)
```
重新编译并刷入内核即可彻底解决 WCN3990 在主线 Linux 下断网与换网崩溃的问题。
